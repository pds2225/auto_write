## 한 줄

과거 자료는 **모듈**로 나누고, 최종 칸은 **이번 공고·양식의 대목차**에 맞춰 재구성한다.

## 왜

정부 양식은 보통 **대목차**만 있다. (예: 1. 사업개요 / 2. 시장 / 3. 추진체계)  
중목차·소목차·제목은 양식에 없거나 빈칸이다. 그걸 양식 대목차만으로 쪼개면 너무 굵다.  
그래서 재료는 모듈 단위로 자르고, 그 모듈을 대목차 아래에 배치한다.

## 계층

```
이번 공고·양식 대목차          ← 최종 배치 기준 (가장 중요)
  └ 중·소목차 / 제목            ← 모듈에서 온 이름
       └ Block / 문장 / 표행    ← 사용자가 고른 재료
```

선택 표시(선택사항): 모듈 카드에 PSST 중 어디인지(Problem / Solution / Scale / Team)를 **표시만** 한다.  
PSST로 최종 칸을 나누지 않는다. 최종 칸 = 공고·양식 대목차.

## 절차

1. **입력**
   - 필수: 공고+양식. 한 파일이 둘을 담을 수 있다. 파일이 2개 이상일 수 있다.
   - 선택: 기존 사업계획서 첨부.
2. **모듈 분해** (파일 단위 복붙 금지)
   - 각 기존 자료를 의미 모듈로 자른다. (문제인식, 경쟁환경, 비교표, BM, 팀 …)
   - 카드에 모듈명 + 실제 원문 미리보기 + 파일명 + 페이지.
   - 클릭하면 원문·표·문단. 세부 선택으로 문장/표 행까지.
3. **양식 대목차 분석**
   - 빈 양식(및 공고 평가항목)에서 대목차만 뽑는다.
4. **재구성**
   - 각 모듈을 가장 가까운 대목차 아래로 넣는다.
   - 한 모듈이 대목차 두 곳에 해당하면 복제하지 말고, 사용자가 어느 대목차에 쓸지 고른다.
   - 대목차에 재료가 없으면 그 칸은 비우고, 생성은 작성계획 승인 후에만.
5. **해당 화면의 파트만**
   - 지금 보고 있는 대목차(또는 그 아래 모듈)만 작성계획 → 승인 → 초안.
   - 문서 전체를 한 번에 쓰지 않는다.

## 작성 우선순위 (칸 내용)

1. **사실 전사** — 소스에 있는 값을 그대로.
2. **비슷한 사실** — 같은 의미의 칸/문장을 찾아 옮긴다. 오매칭은 빈칸보다 못하다.
3. **없음 → 생성** — 만들고 `생성`이라고 표시. 출처 있는 사실처럼 위장 금지.

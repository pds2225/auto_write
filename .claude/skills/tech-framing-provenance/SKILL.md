# tech-framing-provenance — 공고 맞춤 기술 프레이밍 vs 보유기술

> 2026-08-20 STAR-Exploration 위성항법 출처 조사에서 수확.
> 위키: `tech-framing-provenance.md` · 사례: `[[star-exploration]]` · 작성규칙 `[[page-5a8d0a54]]`.

## The Insight

공고가 요구하는 기술 영역(항공우주·국방·KPS 등)에 기존 아이템을 **맞춰 쓴 문장**은
보유 기술·기술이전이 아니다. GPS를 쓰는 보행 앱에 GNSS/KASS/KPS를 붙인 것은
**프레이밍**이다. IR·발표에서 보유·이전·라이선스처럼 단정하면 날조다.

## 언제 쓰는가

- "이 기술 내용 내가 어디서 가져온거지?"
- STAR/국방/킥스업 등 **같은 아이템을 다른 공고 기술축에 맞춰 다시 쓸 때**
- IR·발표자료에서 기술 근거를 쓸 때

## 출처 추적 순서 (광역 스캔 금지)

저장소 `app/` 본문부터 찾지 마라. 개인 사업계획 원문은 커밋되어 있지 않다.

1. **Drive 위키** — 해당 사업 페이지(예: `star-exploration.md`)의 연계 전략·Override 블록.
2. **제출본** — 신청서 아이템명·적용기술 칸(제목이 고도화본과 어긋날 수 있음).
3. **같은 주 다른 공고 신청서** — 기술 스택이 다를 수 있음(STAR≠국방특허).
4. **제품 실체** — 코드·MVP가 실제로 하는 일(예: 스마트폰 GPS 게이팅 ≠ KASS 수신기).
5. **재사용 여부** — 그 문장이 이후 다른 사업(KICXUP 케이네비 등)에 그대로 갔는지.

경로를 모르면 사용자에게 묻는다. 추측으로 출처를 만들지 않는다.

## 판정 규칙

| 층 | 무엇인가 | IR에서 |
|----|----------|--------|
| 원래 아이템 | 도보네비 = 보행 길찾기(사진·간판·이탈알림) | 사실. 근거=제품·관찰 |
| 공고 맞춤 프레이밍 | GPS=GNSS, 항우연=KPS/KASS → 킬러앱처럼 연결 | **연계·실증 추진만**. 보유·이전 단정 금지 |
| 병렬 공고 기술 | 국방경진 특허(10-1974002 등) | STAR에 섞지 말 것(영역 별개) |
| 사용자 Override | 「측위 공백」폐기 → 위성영상+시각연결 주축 | 의도 스토리는 이쪽. 제출 PDF 제목은 옛 프레이밍일 수 있음 |
| 공개지식 조립 | GNSS/SBAS/KASS/KPS/PNT/IMU/PDR 용어 | 논문·기술이전 원문 없음. 인용처럼 쓰지 말 것 |

## 성공 기준

- 출처를 **원문 파일명·날짜·층(원래/프레이밍/병렬공고/Override)** 으로 보고한다.
- 없는 원문을 만들어 대지 않는다(날조 0).
- 다음 산출물(IR)에 프레이밍을 보유기술처럼 쓰지 않을 한 줄을 남긴다.

## 함정

- 제출 PDF 제목만 보고 "KASS 기반 제품"으로 단정 — 고도화본·위키 Override와 불일치할 수 있다.
- `page-7e8f9587`(각색 시 기간·금액은 신청 사업 기준)과 혼동 금지. 그쪽은 **프로그램 특징**. 이 스킬은 **기술 문장의 소유권**.
- 국방 특허 번호를 STAR 항공우주 근거로 재사용 금지. 위키가 영역을 나눔.
- KPS는 개발 중 → "완성 인프라"처럼 쓰지 않음.
